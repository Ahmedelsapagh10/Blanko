# Architecture

Requirements: [execution directive](EXECUTION_DIRECTIVE.md). Current status: MVP-01 session editor plus separate rendering laboratory. Historical measurements and rejected designs remain in phase reports. No full V1 qualification.

## MVP-01 ownership and commit boundary

`BoardSession` is pure Dart and owns the immutable production `BoardDocument`, identity allocation and bounded sparse inverse command history. Insert/move/delete/undo/redo publish one validated snapshot each, preserve authoritative manifests/settings/order and increment revisions monotonically. Movement resolves parent transforms; subtree delete is atomic and respects inherited locks. The full document/index may rebuild once per commit in this slice; that is a known large-document hardening cost.

`EditorScene` derives existing `DocumentGeometry` transforms/bounds and a `SpatialGrid` from a committed document. It culls in paint order and hits in reverse order with precise pen/shape/line geometry. It owns no Flutter resources. Text/image/frame bounds in this adapter do not implement their production rendering/editing.

`EditorPage` owns/disposes the session canvas controller and focus node. `EditorCanvasController` owns camera, selection, transient pointer state and per-committed-scene `Path` objects; paths/draft strokes never enter document state. Pointer movement repaints the canvas with a mutable preview, without copying committed documents or rebuilding the index. Pointer-up commits once; cancellation/tool switch/Escape/focus loss discard the preview. Late pointer callbacks after disposal are guarded. Toolbar notification is separate from continuous canvas painting.

The direct painter owns no images/pictures/async caches. It paints viewport-culled root pen/shapes/lines in source order with local transforms after subtracting the camera origin in Dart doubles. Grid spacing adapts to zoom. Selection movement is a transient world delta. No benchmark scene conversion or experimental raster strategy enters the product. Full nested opacity/content/asset rendering remains future scope; the editor currently creates root elements only and exposes no importer.

## Implemented boundaries

- `lib/main.dart`: normal `WhiteboardApp` → `EditorPage`. `lib/benchmark_main.dart`: separate feasibility runner.
- `src/geometry/geometry.dart`, `src/viewport/camera.dart`, `src/spatial/spatial_grid.dart`: pure Dart affine geometry, world/viewport conversion and incremental ordered broad phase.
- `src/benchmarks/benchmark_scene.dart`: synthetic immutable transform-only scene with stable paint order, group resolution and chunked deltas. Explicitly not a portable document schema.
- `SceneRenderer`: owns prepared paths/paragraphs, synthetic originals, derived spatial index and optional raster caches. Synchronization validates matching deltas before mutating derived state. Content/structure changes are intentionally unsupported in the spike.
- `SceneTileCache`: bounded 64 MiB published images, 512-pixel interiors plus gutters, one asynchronous job, stale-result suppression and disposal. Temporary/in-flight/driver resources are additional. Tiles and mixed recovery default off.
- `ScenePictureCache`: opt-in ordered vector pictures (256-entry source ranges, split around up to 32 active entries), 128 handles/16 MiB approximate LRU. Full paths recorded around local origins; exact visible membership controls reuse. Active entries stay live in their original order; validated deltas invalidate inactive ranges. This remains vector-only; separate on-screen layer experiment follows below. No production adoption.
- `SceneLayerCache` / `BenchmarkLayerCanvas`: default-off composited static subtrees around live active entries, exact camera/membership key,33 subtree/16MiB approximate picture/64MiB estimated raster-exposure caps and full direct fallback. Layer handles and picture ownership are renderer-local; estimates do not bound total GPU memory. Tested retained engine submissions, strict pixel parity, failure cleanup and disposal. Bounded profile evidence exists; Chrome stays over budget and interleaving falls back. Native dense-only prefix benefits; no production adoption.
- `src/document/document_geometry.dart`: snapshot-derived world/inverse maps, one iterative parent-first composition pass, constant-time point lookup and actionable numerical/missing-ID errors. No per-pointer snapshot mutation or renderer resources.
- `src/document/element.dart`, `src/document/document.dart`: independent pure Dart immutable core content/IDs/order/ownership snapshots, JS-safe document/element revisions and general opacity. No Flutter resources, storage, commands or renderer integration. Title, workspace binding, deterministic canvas/grid settings and declared assets/fonts/UTC metadata now exist in `document_settings.dart`. Explicit null manifests preserve unresolved legacy callers; supplied manifests validate references. Visual bounds/hit/index services remain incomplete.
- `BenchmarkPage`: owns renderer sessions, camera, timers, telemetry, selection and transient movement. Repaint listeners avoid widget rebuilding on each camera tick.

## Next boundary

Preserve geometry/index and benchmark fixtures. Production core contracts now represent content/style/structure/revisions independently from Flutter resources; title/metadata/settings/resource declarations now exist; production initialization/import must enforce completeness. Commands produce atomic deltas; pointer previews stay transient. No new state-management, DI, dependency or second rendering engine is adopted. Document/editor integration depends on rendering qualification; independent contracts/tests may proceed.

Dirty-region repair remains a tested, default-off experiment; partial benefit was insufficient for promotion. Vector-range retention is also default-off, with host/Chrome correctness evidence and focused profile diagnostics. See [decisions](DECISIONS.md) and [performance](PERFORMANCE.md).

Execution05 font control (ADR-013): `BenchmarkFonts` owns one engine-lifetime registration set over four fixed local TTF files; scene/document state owns no font bytes or handles. The app gates its theme/scene, renderer creation independently checks readiness, and asset failure/timeout prevents READY with an actionable retry. Ready callers avoid an unnecessary async boundary; partial registration retries skip completed faces. File integrity/coverage/licensing comes from the reproducible verifier, not the SDK's void font-registration result. Combined preparation time includes reads/registration; navigation timing additionally includes engine startup. Local default manifest Roboto avoids the installed web engines' implicit remote default font; shared pubspec has asset/font additions but no new package. Production curation remains pending.

A test-only conditional asset bridge supplies generated, hash-verified font copies through the supported AssetManager API because Chrome widget tests suppress platform asset messages. Custom fonts enabled, download fallback disabled; other test-environment controls retained. This tests genuine paragraphs and changes the old Ahem evidence conditions. Renderer scalar tile cache now detects nonbucket scale in text-bearing scenes using a once-computed immutable flag and completely falls back to ordered direct paint, reporting the event. No text-on-top overlay or per-frame full-scene scan. Preparation/repair lifecycle remains observable; fractional pixel tests prove fallback, not repaired raster fidelity. Scale-aligned cache tests remain; unobserved global subpixel phase and navigation performance still require qualification.
