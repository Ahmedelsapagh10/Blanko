Alternatives: further tile variations, narrower guarantee, or bounded ordered retained content/transient prototype. Decision: retain tested repair default-off and reject promotion. WB-0116's experimental stopping rule now explicitly permits rejection after matched focused failures; the full product rendering/cold/memory/input gate remains unresolved, with no target waived. Native reference/repair both three rows, zero reported lifecycle/viewport changes; visibility checked before runs, focus events unavailable and continuous occlusion unverified. Evidence: per-target dirty-repair summaries, final-source/binary hashes and verification JSON.

Next WB-0119 compares ordered retained vector ranges and limited on-screen layer reuse against the current paths. Keep the same scene/index and authoritative order, with a transient selected set; do not raise moving items above intervening content. Bound range count/resources and use direct fallback for fragmentation. Preserve camera-origin subtraction and culling; each retained range needs conservative bounds and explicit picture/layer lifecycle. Native engine automatic raster reuse is a hypothesis to measure, not an accepted memory or speed guarantee.

Trade-offs: vector ranges may reduce recording while leaving raster cost; separate layers may enable retained raster work but add memory/overdraw/first-use stalls. Manual raster ranges would multiply tile population and carry the same asynchronous cost, so are not the default next choice. Capture first-use command clocks, overlap/alpha/fractional/large-world/cancel/commit/disposal pixels and independent matched profile distributions before adoption. No second engine, content omission, persistence or editor integration on an invalid foundation.

Use direct fallback for unsupported fragmentation, unsorted/duplicate caller order, oversized candidates and spans above 65,536 world units. Record around a local origin and translate relative to the current camera in Dart doubles. No raster images are created by this cache. APIs checked against installed Flutter 3.41.9 and official [Picture](https://api.flutter.dev/flutter/dart-ui/Picture-class.html) / [drawPicture](https://api.flutter.dev/flutter/dart-ui/Canvas/drawPicture.html) docs.

This clock excludes raster/presentation; synthetic originals/load timings remain separate. Independent review also found and removed overview preparation from later retained diagnostics/manual move completion.

Stopping rule: if dense single/multi remain over the unchanged 16.7 ms stage target or regress, reject promotion before an expensive full navigation/cold/soak qualification sweep. Native narrower-view stages improve slightly but normal regresses (5.05→6.136 ms); this does not satisfy cross-platform qualification. Preserve the 16.7 ms target and all required densities/platforms.

Reassessment: more vector chunk tuning cannot by itself establish retained raster benefit. Another manual tile variant repeats known whole-image allocation/queue risk. Changing content fidelity/density or using a second graphics engine is unjustified. The next bounded investigation is actual Flutter on-screen layer reuse around in-order active entries, with explicit range count, device-pixel footprint, first-use/zoom, stale-content and disposal controls. Estimate/account that exposure and use direct fallback before adoption, then measure actual engine/process memory. No layer prototype or automatic raster reuse is claimed yet.

WB-0119 stays IN_PROGRESS because its layer/navigation/cold scope is incomplete. The vector subset's early-rejection rule does not check the parent task or WB-0114. Independent pure-Dart document/transform contracts may continue without renderer integration. Evidence: execution-02 per-target strict summaries, profile manifest, native visibility controls and environment-pressure audit. First native wrong-delay capture excluded, failed builds preserved, no statistical repeatability/physical-presentation claim.

## ADR-008 — Separate production contracts from the synthetic scene

Date: 2026-10-18. Status: scoped model/transform implementation verified on host/Chrome; no renderer integration.

Use caller-supplied opaque IDs, immutable content and one authoritative sibling order represented by relative source occurrence plus parentId. Lookup/children/depth-first order are derived; only groups/container frames own children, independent of bounds. Export frames never own. Element/document revisions are explicit integers 0…2^53−1 for exact Web ordering; snapshots reject elements newer than the document. General opacity is finite 0…1 and separate from per-color alpha. No automatic revisions/ID generation, Flutter resources, text layout/IME, commands or codecs enter this boundary.

Constructor graph validation is iterative O(n) rather than recursive ancestor walking, and is intended for whole snapshot validation; future commands still need incremental structural sharing rather than rebuilding these snapshots per pointer event. Metadata/title/canvas settings/asset/font manifests remain missing under WB-0201, and derived visual bounds/world composition/hit/index validation remains separate. No completion credit for these future contracts from typed model tests.

World transforms now resolve once per immutable snapshot into world/inverse maps in O(n), using parent-first derived preorder; point lookups are O(1). Composed/point overflow fails with element IDs. Nine tests include manual and 200 seeded affine routes, ±1e9 at declared 1e−5 tolerance and 5,000 nested owners. This is independent WB-0204 evidence, not a mutation-performance or visual-bounds guarantee.

## ADR-009 — Bounded on-screen layer experiment

Date: 2026-10-18. Status: implementation/correctness verified; bounded Profile diagnostics recorded below, no production adoption.

Following ADR-007, test maximal ordered static runs split around at most32 active entries. Each run owns an OffsetLayer → ClipRectLayer → PictureLayer subtree via LayerHandle; PictureLayer alone owns/disposes its picture. Append unchanged subtrees with PaintingContext.addLayer, preserving active entries' original order and reacquiring the canvas afterward. Record relative to the camera in Dart doubles, bound recording with a two-logical-pixel margin and use one exact AA composited viewport clip, apply incoming widget offset once. This is framework composited retention, not an assumption of GPU raster caching. Stable addToScene submission counts must be tested independently of pixels. APIs verified against installed Flutter3.41.9 plus official [PictureLayer](https://api.flutter.dev/flutter/rendering/PictureLayer-class.html), [LayerHandle](https://api.flutter.dev/flutter/rendering/LayerHandle-class.html) and [PaintingContext.addLayer](https://api.flutter.dev/flutter/rendering/PaintingContext/addLayer.html).

Caps:33 static subtrees,16MiB approximate picture bytes,64MiB estimated raster exposure. Estimate full projected paint union without viewport intersection, at least the entire explicitly clipped viewport to cover ink outside authoring boxes, rounded outward with the recording margin scaled by DPR, extra AA margins and2× allocation allowance. This estimates exposure, not total/hard GPU memory: driver/cache duplication and borrowed images/paragraphs are additional. Exceeding any cap uses complete direct fallback, never omitted content. Max world span65,536; published resources bounded, one constructed picture additional temporarily. Inactive committed deltas invalidate affected ranges, active entries remain live. Renderer owns handles and disposes before resources; render box subscribes only while attached.

Initial cache key includes exact camera viewport,zoom,DPR and visible membership. Navigation/zoom therefore rebuilds; no navigation benefit is inferred. This first experiment isolates fixed-camera editing. Report first-use CPU clocks without warmup, lifetime builds/reuse/engine submissions, actual samples/commits/visible density, estimates and available process/engine memory. Compare final same-source profile direct/vector/layer arms with equivalent controls, serially. If edits improve, extend cold/zoom/navigation/soak coverage and compare tile strategy before acceptance; if insufficient, stop promotion and reassess. No16.7ms target/density/fidelity/platform guarantee changes. WB-0119 and WB-0114 remain unchecked until their full scope is verified.

## ADR-013 — Controlled benchmark fonts and explicit fractional text containment

2026-10-19; implementation under verification (WB-0120), no product font-policy or rendering promotion.

Problem: prior READY did not guarantee completed Arabic fallback; installed CanvasKit/skwasm also fetch default Roboto when FontManifest lacks exact family Roboto. Historical frame/startup results cannot isolate text readiness or font metrics. Official installed engine sources inspected; [FontLoader API](https://api.flutter.dev/flutter/services/FontLoader-class.html) and [AssetManager API](https://api.flutter.dev/flutter/dart-ui_web/AssetManager-class.html) verified.

Decision: bundle unmodified static hinted Roboto3.015 weights400/500/700 and full NotoSansArabic2.012 regular, with original OFL notices, immutable upstream provenance and SHA-256. Local manifest Roboto supplies engine default; unique lab aliases register all faces once, await readiness before UI/paragraphs, fail with actionable retry and bounded asset waits. Theme and scene paragraphs use explicit Latin/Arabic families. Engine registrations live until engine shutdown; scene disposal does not unregister or repeatedly register them. SDK void registration discards a web decoder false result, so readiness alone is not a validation of arbitrary font bytes: audited fixed files and browser transfer evidence are mandatory. Four font files1,676,168 bytes; extra default Roboto face and engine copies are not a measured memory cap. Combined preparation includes reads and registration; pre-Dart engine startup is only included in navigation clocks.

Browser correctness tests previously forced Ahem and ignored asset platform messages. Test-only supported conditional bridge supplies hash-verified generated font copies through AssetManager, allows explicit custom fonts and disables downloaded fallbacks. Copies are ignored and regenerated by the verifier/batch preflight. This expands correctness conditions; it is not a production SDK patch or comparable typography baseline to old Ahem tests.

Discovery: real fonts fail the existing fractional tile ink bound even before edits:1.25× view uses2× bucket followed by filtering, dark-pixel counts324 versus266 and mean channel-byte error0.7133. These threshold counts do not prove missing glyphs. Exact scale-and-phase raster keys would churn on navigation; drawing live text above cached shapes breaks order/alpha. Contain the observed mismatch by complete ordered direct fallback for text-bearing tile scenes at nonbucket display scales. Cache maintenance and actual aligned cache tests remain; O(1) immutable text-presence guard, explicit counter/reason, original tests strengthened to exact fallback pixels. Matching scales with fractional camera/widget/device offsets remain unqualified. Do not claim the fractional test proves repaired-raster fidelity or that the prior zoom performance is preserved. Candidate remains default-off;16.7ms target unchanged.

Alternatives: retain remote fallback (uncontrolled startup/metrics), substitute SDK Noto Naskh (different design), dynamic variable-font tooling (unnecessary dependency), unqualified overlay text (incorrect ordering), raise raster resolution/relax pixel bounds (not justified). Fixed asset metrics differ from historical unpinned defaults; new profiles establish their own controlled baseline. Arabic shaping, IME/editing, arbitrary Unicode and required platform validation remain separate obligations. Source/release URLs and archive/file/license hashes: assets/benchmark_fonts/manifest.json; execution05 audit/failure evidence preserved.

## ADR-016 — Keep the native window until save-aware exit completes

Real fault injection showed red Close hid the macOS window before Flutter cancelled termination for a failed save, leaving an inaccessible running session. Redirect MainFlutterWindow.windowShouldClose to NSApplication.terminate and return false, using the existing FlutterAppDelegate async termination protocol. XIB/FlutterViewController do not install another window delegate. No new package or framework suppression. Real repeat kept the failed4-element board visible, blocked switching, then permission restore+Retry acknowledged it; a saved red Close exited and relaunch restored all records unchanged. The early failed test's disposable unacknowledged stroke was lost only during deliberate cleanup of its hidden test process; prior acknowledged bytes remained intact.

`AppLifecycleListener` is cancelable only where the platform supports it ([API](https://api.flutter.dev/flutter/widgets/AppLifecycleListener/onExitRequested.html)). Browser unload warns rather than promising asynchronous completion. Native directory fsync/power loss, OS forced termination and unacknowledged survival are not claimed. Future multi-window lifecycle must revisit this single-window close policy.
